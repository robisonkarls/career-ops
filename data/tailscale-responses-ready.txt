3. "Describe a time you shipped something complex under constraints."
────────────────────────────────────────────────────────────────────────────────

**The Dayforce SDD Framework** — Agent-native development at scale.

**Constraint 1: Production system, no room for error**
We needed to increase development velocity on identity and distributed systems code. 
Traditional approach: hire more engineers. Impractical: deep domain expertise not scalable. 
Solution: Redesign the workflow to leverage agents without sacrificing quality.

**Constraint 2: Heterogeneous tooling**
Jira (specs), GitHub (code), internal systems (company-specific standards). Couldn't rely on 
a single platform. Built custom skill orchestration to bridge them.

**Constraint 3: Business context awareness**
Simple code review isn't enough. The agent needed to understand *why* code changes—connect 
back to user story intent, validate business value, not just syntax. Built context layer 
to pass user story details to PR review agents.

**What we shipped:**
- Spec-driven task generation from user stories
- Automated business-context-aware PR review
- Zero compromise on code quality metrics
- Measurable velocity increase

**Why it matters**: This teaches the discipline required for production agent systems. Not 
"use ChatGPT to write code faster"—it's "redesign your system so agents work better than 
humans at specific tasks, while humans remain the decision makers."

4. "What do you see as the biggest opportunity in AI infrastructure?"
────────────────────────────────────────────────────────────────────────────────

**Agent-native platform design** — Most infrastructure is built for human operators. The 
next generation needs to be designed *for agents*, not retrofitted with APIs.

Example: Tailscale's MCP gateway vision. Agents don't need a GUI to provision VPN tunnels; 
they need a spec-compliant interface, clear contract, business-context awareness, and audit 
trails. Your platform's design shapes what agents can do.

The companies that win will be those that:
1. Think about agents early (not as an afterthought)
2. Design for business-context awareness (agents need to understand intent, not just syntax)
3. Build observability first (audit, trace, debug agent decisions)
4. Maintain human oversight (agents make mistakes; humans catch them)

I've done this at Dayforce on engineering workflow. Tailscale can do this for connectivity.
